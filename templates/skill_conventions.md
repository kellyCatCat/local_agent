# 本地标准补充（与模板规范冲突时，以本文件为准）

以下约定来自本地 skill 库中的标准 skill（如 isis-troubleshooting），生成和修改 skill 时必须遵守。

## 文档头部

- SKILL.md 与每个 reference 文件的头部都带 `version`（x.y.z）。新建 skill 写 `version: 1.0.0`；修改已有 skill 时保持原值，不要自行改动。
- reference 文件的 description 写成「<故障名>排障·场景X：<场景名>。<适用时机>」，例如：
  `description: IS-IS排障·场景F：IS-IS 路由无法形成负载分担。只能从一台设备学习到路由，无法从另一台学习到相同业务网段路由时使用。`

## SKILL.md（多场景）

- 前置检查条目只写「CLI 命令」「采集内容」（能在采集阶段判定根因时加「根因定位」），**不要求**「适用场景」。
- 场景跳转表的「跳转场景」列写成 `→ **场景X**：<场景名>（reference/<文件名>.md）`。场景名与参考文件表、场景文件标题逐字一致，路径与参考文件表一致。
- 场景跳转表之后可以有「**说明**：」及若干「- 若…」条目，写多个判据同时命中时的优先级和特殊分流规则。
- `# 排查步骤` 的参考文件表之后，写一段修复下发规则（命中根因后从根因对照表查找「修复CLI和方法」下发）。
- 文件末尾是 `# references` 章节，列出 reference/ 下的全部文件：

      # references

      - skills/<skill-name>/reference
        - <文件名>.md

## reference/<场景>.md

- 标题 `# 场景X：<场景名>` 之后，先写一行引用块说明：
  `> 说明：入参列表、前置检查与场景跳转表见主文件 `SKILL.md`。本文件内「前置检查步骤 X」即主文件前置检查的对应步骤；「本场景步骤 X」即本文件内的排查步骤。`
- `# 根因对照表` 下先写 `### 场景X：<场景名>`，再写表格。
- 源文档没有给出某个原因的判定观测时，「CLI 命令」如实写"本子图未给出该原因的判定观测"，并说明需要现场确认的内容，不要编造命令。

## 模板之外的执行规则（必须保留）

已有 skill 中模板结构之外的说明段落，例如「设备锚定」「修复前强制检查点」「执行顺序」「接口-邻居交叉比对规则」「补充」、跳转表后的「说明」、修复下发规则等，是给执行 agent 的硬性约束：

- 修改已有 skill 时**原样保留**，除非用户明确要求修改。新增场景需要补充优先级或分流规则时，在原有「说明」条目后追加，不要改写原有条目。
- 新建 skill 时，沿用参考样例中与具体故障无关的通用规则（如设备锚定、修复前强制检查点、修复下发规则），与样例具体故障相关的规则不要照抄。
